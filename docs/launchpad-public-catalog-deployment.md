# 启航第四批：顾客目录分享

只新增分享流程，不改变产品管理、报价、员工权限或平台账号。页面采用简单文字按钮。

## 部署顺序

1. Supabase SQL Editor 执行一次 `supabase/migrations/202610060004_launchpad_public_catalog.sql`。必须已经执行前三批。
2. 新查询运行 `supabase/tests/launchpad_public_catalog.sql`，预期 PASS。检查只读，不写公司资料。
3. Supabase 项目 Settings → API Keys 中复制 Secret key（`sb_secret_...`），直接添加到 Vercel 项目环境变量 `SUPABASE_SECRET_KEY`。类型 Secret，至少选 Production；需要 Preview 测试则同时配置 Preview。不要发送到聊天、不加 `NEXT_PUBLIC_`、不写进代码或 Git。
4. URL 和 Publishable key 保持原值。无需额外服务或公开 Storage bucket。
5. 本地验证并提交后通过 GitHub Desktop Push，等待 Vercel 新提交 Ready。缺少服务端密钥时公开目录文字仍可读取，私有图片读取返回 503；配置后重新部署。

## 流程

- 公司产品目录新增「顾客目录分享」。管理页必须登录并属于有效公司。
- 产品默认不公开（包括现有、新增和 CSV 产品），管理员在分享页逐项允许／停止公开。销售员的新增、编辑、删除权限不能改变公开权限。
- 开启公开前检查名称、编号、标签、分类、说明和照片，里面不能写不希望顾客看到的价格／内部信息。程序不返回结构化价格，但无法识别照片或自由文字中手动写入的价格。
- 管理员可以展开「批量公开设置」，按当前搜索匹配的全部结果批量开启／停止公开，需确认数量（不是仅本页）。每批最多 10,000 项，超过则缩小搜索范围；预览数量改变会拒绝操作要求重读。不会修改价格或删除产品。
- 员工保存姓名和带国家码的工作 WhatsApp 后创建链接。默认全部允许公开产品，也可挑选 1–1000 项。每次创建最多 100 个仍有效链接／员工／公司，避免误操作堆积。
- 搜索、翻页不会丢失选择；生成失败保留名称和已选内容；同一请求重试不会创建第二条或延长有效期。
- 已生成链接的名称仅内部可见。员工看自己的链接，管理员看公司的全部链接并可撤销。
- 七天从服务器创建时间计算，不可续期、修改范围或更换联系人；要更改则撤销并生成新链接。
- 全部目录链接动态反映当前公开产品；挑选链接只显示该组仍公开、未删除的产品。取消公开会立即阻止新的产品、照片及询价请求。
- 分享时记录员工姓名和工作号码，避免后台无声换收件人。更改工作号码永久撤销该员工所有旧链接，需生成新的；单纯改名不改旧链接的姓名。
- 顾客无需登录，在 `/c/<随机token>` 查看、搜索和分页（50 项／页）；可展开详情图片，WhatsApp 询价包含产品编号和名称。
- 询价跳转前再次检查链接和产品；已失效链接不能继续获取新的询价跳转。
- 不新增顾客购物车、订单、付款功能。

## 安全边界

- 随机 token 为 256 位能力凭证。持有完整链接的人都能访问到期前的公开目录，并看到该销售员工作号码；这不是绑定某一顾客身份的登录链接。不要将链接发布到不合适的地方。
- `catalog_links` 开启 RLS，仅活跃同公司员工本人／管理员 SELECT；没有客户端 INSERT、UPDATE、DELETE 权限。创建／撤销由受限 RPC 完成。
- 访客只能调用价格字段白名单 RPC，不能直接读取产品表、公司内其他资料、报价、客户或链接表。HTTP 层再过滤一次白名单。匿名公开照片 RPC 仅返回该链接授权的照片路径，没有直接 Storage 权限。
- 服务器先使用匿名 RPC 检查照片，再以 Secret key 读取固定私有产品 bucket 中的受检路径；下载后再次检查。密钥不接收访客参数，不进入客户端，原始 Storage URL／可转发的长效签名 URL 不发给顾客。
- 公开页、数据、图片和询价响应禁止缓存，设置 no-referrer、noindex/nofollow/noarchive。没有第三方图片地址或分析脚本。顾客打开页面每分钟／切回窗口会重查，七天到期由客户端计时清空；撤销以数据库每次请求的检查为准。
- 员工停用／移除、公司停用／过期、号码改变会永久撤销旧链接。恢复员工、重新邀请、恢复公司或续期不会让旧链接复活。公司时间自然到期立即阻止访问，随后续期也会撤销旧链接。
- 已展示、下载、截图或发送出去的内容无法撤回，已经打开的页面可能在下一次检查前显示此前内容，不保证擦除顾客设备中的资料。
- 私有图片经 Vercel 转发，不缓存，会增加 Vercel/Supabase 流量；图片缩略图优先、懒加载、每页 50 项。无公网项目级分布式限流／WAF配置，本批不宣称防止所有爬虫或滥用。正式大量公开分享前应观察流量并按需设置平台防护。
- 平台 Secret key 绕过 RLS，必须仅由项目负责人保管。产品取消公开不是撤销已经下载的图片。

## 本地验证与线上验收

自动测试覆盖真实 PostgreSQL 的公开字段、RLS、选定范围、公司隔离、流水重试、七天、撤销和恢复不复活，以及 API 白名单／照片失效检查。
手机尺寸浏览器检查用本地模拟服务，不连接真实客户资料；需要部署后用真实手机验收。

在测试公司进行：

1. 管理员允许两项产品公开，其余维持不公开。
2. 员工确认个人设置的姓名和 WhatsApp，创建「全部」链接。无痕／未登录窗口打开：只见公开产品及图片，不见价格、登录要求、购物车或付款；搜索可用。
3. 点击 WhatsApp，确认工作号码、编号和名称正确（不必真的发送测试讯息）。
4. 员工挑选一项创建第二链接，确认仅这一项；管理员停止公开后该产品及照片不再可新读取。
5. 撤销链接，无痕窗口刷新应失效。其他员工看不到该链接管理记录；管理员可查看并撤销。
6. 测试员工停权再恢复，旧链接仍失效；如测试公司停用则恢复后也需新生成链接。
7. 更改工作号码会使旧链接失效，确认新链接联系人正确。不要用真实销售员做停权或号码变更实验。
