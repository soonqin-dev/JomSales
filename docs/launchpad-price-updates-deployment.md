# 启航第五批：CSV 批量调价

## 部署

1. 在 Supabase SQL Editor 执行一次 `202610060005_launchpad_price_updates.sql`，必须已执行前四批。
2. 新查询运行 `supabase/tests/launchpad_price_updates.sql`，预期 PASS。只读检查，不修改公司资料。
3. 本地提交后 GitHub Desktop Push，Vercel 确认新提交 Ready。无需新增环境变量。

## 使用

- 入口仍是管理员的「目录设置与导入」，新增折叠的「CSV 批量调价（管理员）」。原来只新增 CSV 不改变；销售员即使有产品新增／编辑／删除权限也不能批量调价。
- CSV UTF-8，5MB／10,000 条／40 列，支持逗号、分号、Tab、BOM、引号及换行。
- 只映射 SKU 和新价格；其他列不使用、不写产品。支持 NewPrice／新单价等表头；字段不明确时手动选择。
- 编号匹配本公司未删除产品，不区分大小写／首尾空格，不转换成数字，前导零保留。不存在不自动新增，重复编号的全部行跳过，避免同一产品使用哪一行价格不明确。
- 空白不是零；零元允许。金额非负，最多两位小数，上限 RM 9,999,999.99；不自动四舍五入多余小数。
- 预览列出原价、新价、可修改、价格相同、不存在、格式错误。预览不写价格。页面最多显示 20 行，下载完整检查／结果可查看所有行（含原价，便于留档）。
- 确认后每批 100 行；当前批次完成后可暂停、继续。成功行保留，冲突行跳过；没有全文件事务或自动回滚。重新预览／刷新页面不撤销之前已改价格。
- 产品在预览后有任何修改（含改名、取消公开），会因 revision／原价不符跳过；删除或编号更改也跳过。不强行覆盖其他设备修改。
- 任务 UUID＋行号＋payload hash 幂等。网络丢失回复，保留本页重试得到原处理结果，不重复改价，也不覆盖后来的变更。修改 CSV／列映射后需新预览，不把旧任务改成另一批数据。
- 同一任务不能再次修改同一产品。每行更新和记录原／新价格、姓名、编号、操作者、时间、前后 revision 在同一事务中提交。管理员可以通过受 RLS 保护的操作记录表留档；本批不增加新的历史管理页面或自动撤销按钮。
- 原名称、图片、标签、单位、分类、说明、类型和公开设置保持原样；只有 price、revision、updated_at 改变。
- 已保存报价及当前内存报价清单不自动调价；新选择的产品在目录刷新后使用新目录价格。
- 重试／暂停进度仅在本页内存，刷新／离开会丢失当前进度，但服务器记录和已修改价格保留。离开会提醒。无本地业务储存。

## 线上验收（只用测试公司）

1. 准备 SKU、Price 两列，包含两个已存在编号、一个不存在、一个重复编号、一个错误价格。
2. 预览检查新旧价与跳过原因；未确认前产品目录价格不变。
3. 确认后刷新目录，新价正确，其他资料不变；此前已保存报价仍旧价。
4. 同一文件重新预览，已更新行应显示价格相同，不再修改。
5. 另一设备在预览后编辑一项，再确认；该项提示冲突，没有覆盖另一设备修改。
6. 继续测试原只新增导入，已有编号仍跳过。

私有权限、跨公司、冲突、任务重试和历史快照使用实际 PostgreSQL 测试；浏览器测试使用本地模拟 API，生产真实手机体验仍需部署后验收。
