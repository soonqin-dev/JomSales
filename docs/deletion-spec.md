# 删除公司与删除账号规格 V1（负责人 2026-10-08 确认：备份含 CSV + PDF；正管理员须先换人）

日期：2026-10-08。只在平台后台（`/platform`）由平台负责人操作。商家管理员、员工都没有删除公司或删除账号的入口。

## 0. 已确认的决定（负责人 2026-10-08）

1. 删除公司、删除账号都只在平台后台进行。
2. 两段式：先进入**回收箱 30 天**，期间可以恢复；30 天到期自动永久删除，也可以由平台负责人**强行提前删除**。
3. 删除前提供**历史报价备份导出**。
4. 账号用「做法A」：不删除 Supabase 记录。永久删除时清空个人资料，只留「已删除用户」空壳记录，后台显示为已删除用户。

## 1. 删除账号

| 阶段 | 登录 | 同一 Gmail 重新注册 | 资料 | 后台显示 |
|---|---|---|---|---|
| 正常 | 可以 | — | 全部 | 正常 |
| 回收箱（30 天内） | **封锁**，不能登录 | **不能**（Gmail 仍属于旧账号） | 全部保留，可一键恢复 | 「回收箱 · 剩 N 天」 |
| 永久删除（到期或强行） | 不能 | **可以**，会是全新账号 | 姓名、WhatsApp 清空；Gmail 换成内部占位邮箱 `deleted-<id>@jomsales.invalid`，原 Gmail 只保留不可逆的哈希供核对 | 「已删除用户」 |

- 进入回收箱时：同时停用此账号在所有公司的成员身份，撤销他分享的顾客目录链接（沿用现有停用员工的规则）。
- 恢复：解除登录封锁，资料原样回来；公司成员身份**不自动恢复**，需要公司重新邀请或由你在平台后台恢复成员。
- 历史报价：报价上保存的建立者姓名和邮箱是当时的快照，永久删除后**不改**，旧报价照常显示原建立者。
- **保护**：平台负责人账号、任何公司的正管理员不能直接删除；正管理员要先在平台后台换人，才能删除。

## 2. 删除公司

| 阶段 | 公司访问 | 资料 | 后台显示 |
|---|---|---|---|
| 正常 | 可以 | 全部 | 正常 |
| 回收箱（30 天内） | 全体成员不能访问（等同停用） | 全部保留，可恢复 | 「回收箱 · 剩 N 天」 |
| 永久删除（到期或强行） | — | 公司的产品、图片文件、报价、客户、分类、分享链接、邀请全部物理删除 | 只留一条平台操作记录（公司名、删除时间、操作人） |

- 删除公司**不删除**任何登录账号。成员登录后会看到「等待公司邀请」，可以被邀请进别的公司。
- 进入回收箱前必须先完成第 3 节的备份（可选择跳过，但要再确认一次）。

## 3. 历史报价备份导出

- 进入回收箱前，以及回收箱期间，都可以在平台后台下载备份。
- 内容：所有报价（含回收站内的）的 CSV 汇总（编号、日期、客户、状态、金额、建立者、项目明细）+ 客户通讯录 CSV + 产品目录 CSV。
- 也包含每张报价的 PDF（负责人已确认）。ZIP 第 1 部分含全部 CSV；PDF 每 80 张一个 ZIP，按部分依次下载。生成失败的 PDF 列在「PDF生成失败.csv」，CSV 资料不受影响。

## 4. 强行删除与双重确认

- 「强行删除」需要：输入公司名称（或账号邮箱）完全一致 + 双重验证码，才会执行。
- 永久删除不可撤回；已下载、已分享的 PDF 和卡片无法召回。
- 每一步（移入回收箱、恢复、到期删除、强行删除、备份下载）都写入平台操作记录。

## 5. 技术说明（实现前必须核对）

- 现有项目**不使用 service-role key**。账号封锁、改占位邮箱需要修改 `auth.users`，计划用只允许平台负责人调用、并要求双重验证的数据库函数完成。
- **风险**：较新的 Supabase 项目可能不允许 `postgres` 角色直接修改 `auth` 表。实现前会给你一条只读的检查 SQL，在 SQL Editor 跑一下确认权限；如果不允许，账号封锁改为应用层封锁（登录后立即拒绝并退出），占位邮箱改为在 Supabase 后台手动处理。
- 到期自动删除沿用现有 `pg_cron` 每小时任务的做法（同报价回收站）。
- 新迁移、隔离数据库测试（PGlite）、SQL Editor 验证脚本，三样都会提供；不会改动现有数据，直到你执行迁移。
